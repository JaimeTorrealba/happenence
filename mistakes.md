# Mistakes

- 2026-10-01: In the Decap CMS local-testing steps I didn't say that `decap-server` (port 8081) is a background API and not something to open in the browser, so the user opened it and got "Cannot GET". When giving setup steps for a first-timer, say which URL to open and which processes only need to keep running.
- 2026-10-01: I gave `http://localhost:3000/admin/` as the local CMS URL without checking that Nuxt's dev server maps `/admin/` to `public/admin/index.html`. Use `/admin/index.html` locally unless that mapping has been confirmed.

- 2026-10-02: Planned a custom `/raw/[...slug].md` server route before checking the installed `@nuxt/content` — v3.16 already ships it (plus llms.txt integration) when `nuxt-llms` is installed. Check node_modules for built-ins before planning custom code.
- 2026-10-02: Used static `src="/images/..."` in a Vue template for assets that didn't exist yet in `public/`; Vite tried to resolve them and crashed with ENOENT (`C:\images\...`). For placeholder/not-yet-added public assets, bind `:src` to a string so they stay runtime URLs.
- 2026-10-02: Put a plain `.ts` shader module inside `app/components/about/`. Nuxt auto-registers files in `components/` (including .ts) as components, so non-component helpers don't belong there. Inline them in the .vue file or put them in `utils/`.
- 2026-10-02: Compared `route.path === item.to` exactly in SiteNavbar, so `/about/` (trailing slash, as static hosts often serve) shows About instead of Home. Normalize trailing slashes when comparing routes.
- 2026-10-02: Ported the Vue Bits Aurora shader as-is and only changed the colours for a light page. Its output multiplies colour by intensity (made for dark backgrounds), which leaves dark grey edges on #f7f7f7 however pale the stops are. Check how a shader composites against the actual page background before tuning colours.
- 2026-10-02: Used `gsap.from` for entrance animations on server-rendered elements. The SSR HTML shows them visible until hydration, then GSAP hides them, so they flash. On SSR pages, set the hidden start state in CSS and animate in with `fromTo`/`to`.
- 2026-10-03: Wrote the cherry tree render loop with `THREE.Clock`, which is deprecated since three r183 and warns in the console (installed: 0.186). Check the installed three version for deprecations before using a core class from memory; the rAF timestamp is enough for simple time-based motion.
- 2026-10-03: A global `main { min-height: 100vh }` made every short page scroll, because the navbar and footer were added on top of a full-viewport main. For "footer at the bottom", use a flex column with min-height 100dvh on the app root and `margin-top: auto` on the footer; never give one section 100vh.
- 2026-10-05: Set Netlify `publish = ".output/public"` because that's where `nuxt generate` writes locally. On Netlify, Nitro auto-selects the `netlify-static` preset, which writes to `dist/`, so the deploy failed. Check the host's Nitro preset output dir (node_modules/nitropack/dist/presets/<host>) before setting a publish path.
- 2026-10-05: For the Decap "OAuth App access restrictions" error I told the user to approve the "Netlify" OAuth app for the org. Decap's github backend on Netlify logs in through the GitHub OAuth app the site owner registered and added under Netlify → Access & security → OAuth, so that custom app (with its own name) is the one the org must approve. Before naming an OAuth app, check which one the auth flow actually uses.
- 2026-10-05: Added only a DRACOLoader for the re-exported cherry tree GLB because the user said "Draco", without reading the file's `extensionsRequired`. It also needed `KHR_texture_basisu` (KTX2), so loading failed with "setKTX2Loader must be called". Before adapting a loader to a compressed glTF, read the GLB's JSON chunk and cover every required extension.
- 2026-10-06: Switched the cherry blossom materials from BLEND to cutout by setting `transparent = false` only. GLTFLoader also sets `depthWrite = false` on BLEND materials, so the opaque cards layered by draw order (material id) instead of distance, and the leaves visibly popped when the fade ended. When changing a loaded glTF material's alpha mode, reset every property the loader set for the old mode.
- 2026-10-06: The cherry tree sway plan put one branch bone on each blossom mesh, assuming the six meshes were separate canopy clusters, after reading only the GLB's JSON (node transforms, accessor bounds). Decoding the Draco positions showed each blossom mesh is spread over the whole canopy with its centre on the trunk axis, so those bones would all have had the same weights. It also picked "lowest blossom vertex" as the fork height, but blossoms hang almost to the ground. Before planning anything that depends on where a model's vertices are, decode the real positions (public/draco/draco_decoder.js runs in Node through `vm`).
- 2026-10-06: The cherry tree dust plan said every existing `renderCherryTreeFrame` call could skip drawing while the dust loop runs. The ResizeObserver call can't: its callback fires after this frame's rAF, and `setSize` clears the canvas, so skipping would flash a blank frame on every resize. When deferring draws to a rAF loop, check whether any caller clears the canvas after rAF (resize, context changes) and draw those straight away.
- 2026-10-06: Edited cherryTreeSway.js with a Python script in text mode, which on Windows rewrote the LF file with CRLF line endings. When scripting edits with Python here, open files with `newline=''` (or fix the endings straight after) so the file's line endings stay as they were.
- 2026-10-06: The petals plan added ~30 lines to HomeCherryTree.vue without checking its length (221), so it went to 252, past the 250-line rule, and needed a split that wasn't planned (bark mesh lookup moved to cherryTreeModel.js). Count the lines a plan adds to every touched file, not just the new ones. It also said the scene's disposal only covers meshes "like the dust", but an InstancedMesh is a mesh, so the scene disposal does reach the petals (disposing twice is harmless).
- 2026-10-06: The grass plan picked a 0.3 radius and only flagged "the front edge may be cut off" as a risk, although the camera framing (fitCameraToCherryTree) and the GLB bounds were enough to work it out: with the tree ~0.88 tall the front edge leaves the canvas above ~0.24. It also only grew the blades with the leaves, so the bare ground disc showed before the intro. When adding scene objects, compute whether they fit the existing framing, and tie every part of a new object to the intro, not just the animated part.
- 2026-10-06: The petal shader cut its shape with `pow(Along, 0.6)` and antialiased with `fwidth(Edge)`. With MSAA, edge pixels are shaded just outside the quad, so Along went negative, pow() gave NaN and `Shape <= 0.001` didn't discard it. The pow() also made Edge so steep at the base that fwidth half-filled the bottom row. Together they drew a grey line at the petal base. In SDF-style fragment shaders, clamp UVs before pow/sqrt, write discards so NaN fails them (`!(x > t)`), and take the antialias width from the coordinates, not from a field with a singular derivative.
- 2026-10-06: Edited index.vue with a Python script that read and wrote with the default Windows encoding (cp1252), so the `×` I added was written as a non-UTF-8 byte. When scripting edits with Python here, pass `encoding='utf-8'` as well as `newline=''`.
- 2026-10-06: The user asked for the home scene to shrink below 1100px and below 560px. I applied the aspect cap at every width instead, so it also shrank at 1280px and 700px, sizes they were happy with. When the user gives breakpoints, scope the change to exactly those ranges, even if a general rule looks cleaner.
- 2026-10-07: Ran `grep -oE '.{0,400}…'` over a 590 KB single-line minified bundle; it hung past the 2-minute timeout. For minified bundles, slice around `str.find()` hits in Python instead of regex context.
- 2026-10-07: Checked line endings with `grep -c $'\r$'` in Git Bash, which counted every line of LF files as CRLF, so I wrongly concluded the edit tools had converted files and ran a needless `sed` to "fix" them. Count carriage returns at byte level (`tr -cd '\r' < file | wc -c`) or use `file` before deciding endings changed.
- 2026-10-07: Deleted the old card components with `git rm`, which also staged the deletions, although the user does all git work by hand. Delete files with plain `rm` so the index stays as the user left it.
- 2026-10-07: The /verify plan listed `/_nuxt/components/about/AuroraBackground.vue` as a compile check, but that component was deleted in afafed4 (About uses SilkBackground now), so the fetch 404ed. I took the file list from the verify skill and older notes without running `ls app/components`. Build verify checklists from the current tree. The plan also said there were no `cards-wrapper` leftovers after a grep that only looked for `CardSwap`/`<Cards`. A dead `.cards-wrapper` rule is still in app.vue. When checking for leftovers of removed components, grep their class names too.
- 2026-10-07: The audit plan said to use `<LazyHomeCherryTree hydrate-on-visible />` inside `<ClientOnly>`. Lazy-hydration strategies only delay hydrating server-rendered HTML, and a ClientOnly child is never server-rendered, so the strategy would do nothing there. Only the `Lazy` prefix helps (it moves three.js into an async chunk). Before planning a Nuxt hydration strategy, check whether the component is SSR'd at all.
- 2026-10-07: The parallax plan put the camera inside a moving group and only checked that fitCameraToCherryTree's lookAt still worked. It missed that cherryTreeDust.js sized the motes from `Camera.position`, which became a local position, so the dust size would have shifted with the mouse. When re-parenting an object, grep for every read of its `.position`/`.rotation` and switch world-space uses to `matrixWorld`.
- 2026-10-07: Put the navbar's drop-shadow filter on the wave SVG only. Both had the same #f6f5f2 in code, but the user saw two different colours, most likely because the filter composites the wave in its own layer. When two elements must read as one shape, define the colour once (a custom property) and put shared effects on their common parent.
